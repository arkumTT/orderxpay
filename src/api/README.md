# src/api — OrderxPay backend

Go + Fiber, PostgreSQL via sqlc + pgx, PASETO v2 (local/symmetric) for
session tokens. Standalone service — the mobile app, back-office, and web
frontends all call this over HTTP.

## Layout

```
cmd/api/main.go          entrypoint: config, db pool, server bootstrap
internal/config/         env loading
internal/auth/           PASETO token issuing/verification
internal/middleware/     Fiber auth middleware
internal/http/           route registration
internal/http/handlers/  request handlers
internal/db/sqlc/        generated by sqlc — do not edit by hand
db/migrations/           golang-migrate SQL migrations (source of truth for schema)
db/queries/              hand-written SQL that sqlc generates code from
```

Money is stored as `bigint` pesewas (GHS lowest unit) everywhere — see
`db/migrations/000001_init_schema.up.sql`.

## Local development

1. `cp .env.example .env` and fill in `PASETO_SYMMETRIC_KEY`:
   ```bash
   openssl rand -hex 16
   ```
2. Start Postgres (from repo root): `docker compose up -d`
3. Run migrations: `make migrate-up`
4. `make run`

Health check: `GET /healthz`

## Route groups (see `internal/http/routes.go`)

- `/api/v1/public/...` — no auth: merchant sign-up, hosted checkout lookup,
  customer-initiated order requests, PSP webhooks
- `/api/v1/app/...` — merchant app auth (merchant owner or staff)
- `/api/v1/admin/...` — Back Office auth (admin_users only)

## What's stubbed, not implemented

A few endpoints intentionally return `501 Not Implemented` because they
depend on decisions not yet made in the architecture doc (which PSP, which
SMS/WhatsApp BSP) or on business logic that needs its own design pass rather
than being scaffolded ad hoc:

- Invoice creation (order/invoice engine — Section 4.3/4.8)
- PSP webhook handling (Section 4.5/9.1)
- Settlement batch reconciliation (Section 7.2)
- Merchant OTP request/verify (Section 4.1/9)

Everything else (merchants, staff, items, delivery options, fee rules,
conversations, order-request review, audit log reads, admin login) is fully
wired end-to-end against Postgres.

## After changing the schema or queries

```bash
make migrate-create name=your_change   # new migration files
# edit db/migrations/..._your_change.up.sql / .down.sql
# edit/add db/queries/*.sql as needed
make sqlc                              # regenerate internal/db/sqlc
```
